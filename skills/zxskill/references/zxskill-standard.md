# zxSkill Standard

This is the user's personal end-to-end thinking-and-writing workflow. It was distilled from the process that produced the accepted final batch of structure-heavy Chinese口播 drafts, then corrected so the workflow starts from 老周式 problem analysis rather than topic selection.

The core idea:

Do not generate from a fixed old template. Do not start from a title bank. Think from a real problem's objective reality, rewrite the question, package it into a topic only after the structure is clear, build a logical article, then remove AI flavor without damaging the user's original thought.

## Full Pipeline

1. Thinking structure analysis.
   - Decide whether a real-world problem deserves this style of deep拆解.
   - Look for objective changes, old-new mismatch, ordinary-person cost, hidden risk, and question-rewrite potential.
   - Drop problems that are only titles, emotions, or slogans.

2. Topic packaging.
   - Turn the worthwhile problem into a title only after the thinking structure is clear.
   - The title should point to the rewritten question, not merely sound catchy.

3. Topic optimization or drafting.
   - Choose an entry mode based on the topic.
   - Start from objective conditions, not from forced "two extremes".
   - Rewrite the surface question into a deeper useful question.
   - Build the chain: old logic, changed condition, structure, scene, trap, personal use.

4. AI-flavor cleanup.
   - Preserve the user's useful original thought path.
   - Remove mechanical symmetry, generic reversals, fake smoothness, and exaggerated emotion.
   - Keep the language spoken, grounded, and slightly human-rough.

5. Final quality gate.
   - Confirm the draft is logically true, realistic, and not template-driven.

## Route By User Intent

- "像老周一样思考/不要从选题入手/哪些问题值得拆" -> use `zxskill-thinking`.
- "这些问题包装成题目/帮我起题/题目方向" -> use `zxskill-topic`.
- "写一篇/改成稿/批量 Markdown/按上次效果" -> use `zxskill-optimize`.
- "去AI味/用dbs检测/只改AI感/保留结构" -> use `zxskill-ai-clean`.
- "从头到尾做" -> run thinking -> topic packaging -> optimize -> AI clean -> final gate.

## Accepted Thinking Order

Use this order when creating or revising:

1. What real problem is worth thinking about?
2. What objective condition changed?
3. What old answer are people still using?
4. Where does the old answer mismatch the new condition?
5. What are ordinary people paying for this mismatch?
6. What is the real question after rewriting?
7. How should it be packaged into a topic?
8. Why did the old belief once make sense?
9. Why does it no longer automatically work?
10. What structure explains the change?
11. What concrete scene proves it?
12. What is the misuse trap?
13. How should the person use the opportunity, risk, platform, tool, window, or choice?

## Entry Mode Decision

Choose one. Do not force all articles into the same opening.

- Fact change: use when the topic depends on changed cost, scarcity, pricing, platform mechanism, or risk.
- Concrete scene: use when the topic is best felt through a family, student, worker, or creator's real decision.
- Common misread: use when one popular explanation is shallow but not entirely wrong.
- Cost/risk account: use when ordinary people are calculating the wrong thing.
- Two public sayings: use only when two real public misreadings naturally exist.

## Core Ban List

- Do not force "一种说法/另一种说法" into every article.
- Do not start with "我要 100 个选题" when the real task is "我要 100 个值得拆的问题".
- Do not choose a content category before finding the old-new mismatch.
- Do not overuse "真正的问题不是 X，而是 Y".
- Do not write "一提就慌" if reality is only "会担心".
- Do not turn every topic into a motivational ending.
- Do not make all paragraphs the same size.
- Do not use placeholder phrases or old generator leftovers.
- Do not rewrite a user's article beyond recognition unless asked for full rewrite.

## Final Quality Gate

Before delivery, check:

- Reality: Does it begin from facts, scene, cost, or changed conditions?
- Problem structure: Is there an old answer colliding with a changed condition?
- Logic: Does each paragraph push the argument forward?
- Rewrite: Is the surface question made deeper?
- Scene: Is there at least one believable ordinary-person scene?
- Specificity: Are abstract claims grounded?
- Variety: Is it not just another version of the same template?
- AI flavor: Are symmetry, generic reversals, and fake polish reduced?
- Ending: Does it return to how the person uses or bears the thing?

## Batch Quality Gate

For many topics:

- Keep source order and numbering.
- Use 1500-2000 Chinese characters per article unless changed.
- Generate from problem archetypes first, not from category/title lists.
- Use varied entry modes.
- Preserve accepted sample articles if the user approved them.
- Rewrite placeholder topics into real topics.
- Remove stale output files before regenerating.
- Create a Markdown directory file.
- Run scans for old template phrases, duplicated transitions, repeated full-title mentions, and overuse of two-saying structure.
